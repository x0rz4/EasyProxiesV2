- 按用户最新要求，阶段 1 起各批次只执行 gofmt、差异检查和静态审查；全部阶段结束后统一运行编译、后端测试与前端检查。阶段 1 新测试尚未执行。
- 后续仍需完成：地区归一/unknown 迁移、查询与保存筛选/预览、前端切换、检测 Applier、容量自愈 dry-run 与执行、Linux amd64/arm64 发布 CI。Docker 流程不改；只创建本地提交，由用户手动推送。

建议按阶段实施，但先明确地区证据、成员资格、健康状态与实际入池选择四个边界，避免让 nodeview 成为同时负责检测、持久化和调度的大包。

- 原版 `boxmgr/landing_location.go` 的确会在 GeoIP 可用且没有成功检测缓存时清空地区。已暂存的 nodeloc 补丁解决这一条路径；它还没有实现来源、乱序保护、集中写入和防抖。
- 节点地区持久化调用目前集中在缓存应用、启动检测、手动质量检测三处。`unlock/ip.go` 生成解锁检测元数据，并不直接调用 `UpdateNodeLocation`。服务解锁地区与节点出口地区必须保持不同事实；只有经过验证的出口 IP 证据才能进入节点地区写入流程。
- `nodefacts` 有 Known/Unknown 值和未知值比较规则，但 `loader.go` 当前仍将空地区转换为已知的 other，schema 和测试也明确依赖此行为。它不是可以直接套用到地区上的完整三值逻辑：Evaluate 返回 bool，组合 MatchNone 还需要专门验证未知值语义。
- `geoip.AllRegions()` 是五个明确地区加 other；实际存储支持任意 ISO 地区码，旗帜输出已经支持通用两字母码。需要补齐显示名称和输入归一，而不是重新实现旗帜输出。
- 前端确有重复地区筛选。GroupPoolsPanel 取消显式成员时，仅凭地区提示“继续自动入池”，没有完整考虑标签和排除规则。文本分隔本身可以留在输入控件，成员结论必须来自后端。
- 订阅刷新已经通过 CommitSnapshot 提交身份和归属变化，已有失败订阅保留归属等测试。先审计并强化现有增量语义，不能将它描述为完全没有增量合并。
- 未找到 min_healthy、target_size 或 refill 实现。现有恢复机制在冷却期内直接忽略成功计数，提前探测不等于提前恢复。
- reflect.DeepEqual 是现有变化检测方式，不能仅据此判定有错误。优化应针对“排序变化或展示字段变化是否引起无效重建”，并保留 URI、代际等运行参数变化的检测。

## 2. 需要先固定的设计契约

### 地区证据与提交

保留小型 `nodeloc` 包负责值类型、归一与纯决策；`nodeview` 负责查询和筛选。由 app 装配共享的地区应用服务，store 提供事务写入接口。monitor 和 boxmgr 经消费方接口接入，不能各自创建独立防抖状态。

Location 保留 ISO、Country、Source、Known、CheckedAt；观测另携带 NodeID、节点身份修订、ObservedIP、ProbeID、观测开始时间或单调序号。Known=true 必须有有效 ISO，other 不是 ISO，也不存入 Location.ISO。失败结果与最后一次成功地区分别保存。

推荐规则：

1. 检测失败、无 ISO、非法 ISO 不改变最后成功地区；可以更新独立的最近检测状态。
2. 节点身份改变或被删除后，旧观测不得写回。保留旧地区的规则仅适用于同一个节点身份，不能让替换 URI 的节点继承旧出口位置。
3. 不接受入口服务器 GeoIP 作为落地区域；geoip_entry 若保留，只作为独立事实。manual 如需覆盖，必须成为显式管理功能，不能伪装成检测来源。
4. 来源与新旧程度分别比较。已接受的新证据不被更旧观测覆盖；同一出口观测内才按明确的来源优先级选择分类结果。避免“优先级更高或时间更新”这个 OR 条件导致任一低质量新结果都能覆盖。
5. 未知到已知首次成功立即接受。地区变化默认需要两个不同 ProbeID 的连续一致成功证据；重复事件、缓存重放以及一次探测的 GeoIP/IP API 两种分类不能算两次。失败或候选地区变化重置候选计数。手动覆盖若实施，单独定义即时生效与解除规则。
6. 一次事务完成身份/版本检查、候选计数和位置更新，返回实际接受后的值、changed 与 reason。持久化失败时不更新运行快照；提交成功后才发布变更通知。运行态同步失败可重试并由周期校准修复。
7. 仅 ISO/Known 的有效变化触发成员资格重算；Country 显示名变化刷新展示。来源和时间变化是否触发标签重算，取决于是否暴露为可查询事实。

防抖状态需持久化或明确重启后重置为零，禁止缓存重放补足计数。推荐与位置同事务持久化候选状态。旧 region/country 暂作兼容投影，所有创建、更新、导入路径都要审计，不能只替换三个显式调用。

### 未知、other 与兼容

- 空地区为未知；普通地区条件及其叶子否定条件不匹配未知，显式 IncludeUnknownRegion 才允许地区筛选接纳未知。无地区条件的通用查询可以展示所有节点。
- other 是固定、版本化常用地区集合以外的已知地区集合。需要明确这是新语义：当前运行时其他国家仍保存各自 ISO，现有 other 主要承接空地区。
- uk → gb 是别名；中文名称、旗帜映射到对应 ISO。cn、hk、tw 是三个独立代码，不互相归并。
- 旧库无来源的非空地区不能直接认定为 exit_probe。标记 legacy_unverified；保留显示，安排复核。只有可验证的成功出口检测才能回填可信来源。
- 对选择 other 的旧分组和引用 node.region 的标签规则先生成影响报告。迁移应保存旧规则版本，旧分组继续按旧语义执行；用户切换新规则时展示成员差异。不能靠给 other 分组加 IncludeUnknownRegion 就宣称完全兼容，因为新 other 还会吸入其他已知国家。

### 查询、成员资格、选择与健康分离

建议定义一个纯规则核心，由 groupmember.Filter 继续作为分组入口适配它，nodeview.Query 也调用该核心。核心不导入 monitor、boxmgr 或 nodeview；nodefacts 继续不认识解锁/provider 实现。避免 groupmember 与 nodeview 互相依赖。

分组顺序保持：禁用组 → excluded → explicit → 地区与标签规则。通用列表的状态、延迟筛选是展示约束，不能无意改变 explicit 绕过分组规则的契约。定义独立的 MembershipSpec 和查询约束，或为同一 Spec 明确区分执行模式。

至少区分：符合规则的候选、已选择入池、运行健康、被全局剔除。ALIVE 不自动等于完成探测且可用；历史/provisional 状态也不应默认计入 healer 的新鲜健康容量。

API 约定：

- nodes/query：校验 Spec 版本、分页上限、排序白名单；稳定排序附加 NodeID；结果包含总数与 snapshot_revision。状态/延迟从同一个批量快照读取，不能逐节点访问 store。
- nodes/facets：第一版明确为全局可见节点统计，并返回 unknown 独立项；若需要筛选后的统计，再支持相同 Spec，明确是否排除当前维度条件。
- groups/{id}/preview：接收尚未保存的草稿规则，不只读取已保存组；新增组另提供无需 ID 的预览。返回候选、选中、当前运行成员的差异与原因、规则版本和快照修订。保存时重新校验，预览不承诺未来成员不变。
- saved_filters：独立追加 migration，保存带版本的 Spec。第一版分组复制规则，不动态引用可变的保存筛选；否则修改筛选会隐式改变运行池。定义删除、改名、引用失效与权限行为。
- 所有新 API 复用现有认证，不将 URI 凭据加入普通查询/预览响应。

### 检测事件与自愈

统一事件格式不等于统一健康副作用。ProbeResult 应带来源、种类、ProbeID、节点身份修订、开始/完成时间与类型化载荷。只有既有健康探测和数据面失败来源可推动健康状态；手动测速、质量、解锁、启动出口探测不得因接入 Applier 而发布健康事件。

先同步应用、返回提交结果，再考虑异步队列。异步化需补齐持久化/重试、去重、按节点次序、背压、关闭排空与重启校准；不能用无确认的内存事件总线代替已完成的落库。

导入提交后发布“需要初检”，由调度器排队；Applier 负责结果应用，不兼任网络探测执行器。既有身份不变的节点保留历史，身份变化清理旧事实并拒绝在途旧结果。

healer 首先需要候选集与 active/standby 模型，否则当前已全量入池的候选无从“提升”。target_size 指实际选中成员上限，必须满足 min_healthy <= target_size；默认关闭容量限制以保持旧行为。备用节点仅从满足原规则且有新鲜健康证据的候选选取，采用稳定排序避免换入换出。

提前探测默认不绕过冷却。若后续确实支持跳过冷却，必须新增显式恢复策略，并解决同一 NodeID 在多个分组中策略不同但恢复全局传播的问题。不能通过更改 evictedAt 或额外发送成功事件绕过状态机。

订阅刷新按订阅去重和限速，增加退避、熔断及全局预算。不能自动放宽地区、标签和排除规则。healer 通过接口请求动作，由 app 装配，group 包不导入 boxmgr/subscription。

dry-run 仅计算并记录拟执行动作；不得启动额外探测、刷新订阅、改变冷却或更新池。事件日志允许持久化，并需去重、保留期限和失败可观测性。

## 4. 验证与发布门槛

- 地区矩阵：失败、缺失、空值、有效变更、同一次探测多来源、缓存重放、乱序、跨身份、并发 Apply、事务失败与运行态同步失败；使用固定时钟。
- 迁移矩阵：空地区、legacy other、已知但无来源、成功缓存、失败缓存仍带旧 IP；迁移重跑与原规则兼容。先备份，再验证升级，不能通过修改已执行 migration 回退。
- 规则矩阵：disabled/excluded/explicit/tag any/all/失效 tag ID/未知/other/别名，以及 nodefacts 的 MatchNone 和 Negate。共用 fixture 比较 builder、boxmgr 与 preview。
- 查询验证：状态快照一致、稳定排序、分页边界、计数、批量加载和大节点集内存开销；UI 检查筛选后的批量操作对象正确。
- 检测验证：事件重复、乱序、节点删除与身份替换、关闭排空；手动诊断绝不改变剔除或恢复状态。
- healer 验证：无备用、健康过期、多个组争用同一节点、不同恢复策略、订阅并发刷新、预算耗尽、熔断、dry-run 无动作、两阶段更新失败和旧连接排空。
- 后端按阶段跑相关包测试，提交前跑 `go test ./...`；涉及并发机制时追加相关包 `-race`（使用支持 race 的环境）。最终验证生产 tags 构建。
- 前端变更必须跑 `npm run lint` 和 `npm run build`。Go 全量测试/构建前准备真实前端 assets；静态评审不能代替实际测试。

## 5. 实施前决策建议

默认采用：不接受入口 GeoIP 作为出口地区；两个独立成功探测确认地区变化；首次成功立即赋值；旧规则版本保留；保存筛选暂不动态绑定分组；提前复检遵守冷却；healer 初次发布严格 dry-run。

需要产品确认的行为集中在阶段 2 的旧 other 迁移、manual 覆盖是否提供，以及阶段 6 的容量选择与全局恢复策略。其余可以按上述默认方案先完成热修和地区服务。

- 暂时探测失败不再删除手动成员；自动恢复开启时，打开编辑器不再把临时剔除固化为永久排除。
