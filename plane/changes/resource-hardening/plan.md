# 资源占用与稳定性修复计划

日期：2026-10-26。基线：2.2.8。状态：实施中。

本批处理源码审查发现的七项资源与生命周期问题。现有 OOM 日志只能证明系统内存分配失败，不能证明下列任一项是生产事故的唯一根因。每项修复独立提交，并在此记录验证结果；本批最后统一递增一次 patch 版本。

## 提交顺序与验收

- [x] R1 探测调用有界：取消十分钟后遗忘仍运行调用的机制；调用实际返回前保持占位和 detached 计数，并给所有未退出调用设置总上限。测试取消后不重复启动、真实退出后恢复、总上限及晚到结果不改变健康状态。
- [x] R2 SQLite 缓存预算：缩小每连接默认页缓存，保留 WAL、单写与四读的隔离语义；提供显式缓存预算配置。验证各连接 PRAGMA、默认值与非法配置，文档写清按需分配而非预分配。
- [x] R3 标签成员更新：把每批变化启动 goroutine 改为有生命周期的合并队列，固定消费者、失败重试、关闭取消。保证不能持标签队列锁执行重建；测试批次合并、失败保留与关闭。
- [x] R4 检测任务持久化：给落库设置超时、报告错误，合并并发进度写入并保留终态持久化。测试数据库阻塞时取消/关闭有界、失败可观察及最终状态。
- [x] R5 全局检测预算：让综合任务、批量与单节点解锁/测速共享按类型的预算，健康探测维持独立预算。测试跨入口并发总数与取消等待，避免嵌套获取死锁。
- [ ] R6 订阅响应体上限：统一旧配置订阅与托管订阅的大小限制；超限明确失败，保留已有节点与窄写语义。测试边界、超限、分块传输及正常导入。
- [ ] R7 连接半关闭能力：按底层实际能力包装连接；缺少能力时走 sing-box 的正常完整关闭路径，保留流量/错误统计与一次性释放。测试支持/不支持半关闭、关闭计数与日志对应行为。

## 共同边界

- 遵守 `docs/code-standards.md`，沿用 HEALTH/DIAGNOSTIC 与成员发布顺序契约；不改健康归因与诊断来源语义。
- 不手改 `internal/httpapi/assets/`；需要前端构建时先完成前端，再运行 Go 构建/测试。
- 不调整 Windows 应用控制策略。测试启动被拦截时区分“编译通过”和“运行未验证”，保留命令与限制，不能写成测试通过。
- 每项提交包含必要回归测试、当前形态文档及本计划的进度。最后做受影响包回归和生产 tags 链接检查；无生产内存采样时不宣称已证明 OOM 消失。
- 指标/pprof 和入口连接限额属于后续专项，本批不扩展为额外功能。
