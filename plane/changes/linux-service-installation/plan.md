# Linux 服务安装优化

日期：2026-10-26。基线 2.2.10。状态：已完成（2.2.11）。

问题：原脚本安装二进制时可生成 systemd 单元，但不能离线为已有程序补注册，不能独立管理开机自启，不支持 OpenRC，也没有覆盖系统服务行为的回归测试。

## 实施范围

- [x] 将安装、离线注册和服务管理共用同一入口；默认安装继续开启自启并启动。
- [x] systemd / OpenRC 自动探测与显式选择，预检 root、运行环境和 supervisor 依赖。
- [x] 服务模板设置工作目录、固定配置路径、失败重启及容纳应用清理预算的停止等待。
- [x] 开启/禁用自启、启动/停止/重启、状态、注销；注销保留配置、数据库和二进制。
- [x] `--no-start` 保持原安装语义，补注册可不立即启动；`--no-autostart` 明确关闭自启，Docker 同步设置 restart policy。
- [x] 原单元升级、同名非托管服务保护、安装目录归属、注册文件原子替换与失败提示。
- [x] 脚本语法、下载/Docker 原有回归与服务生命周期回归；更新当前部署文档并统一递增 patch。

当前形态见 [部署说明](../../../docs/deployment.md)，不改变 Go 运行时、数据库 migration 或应用 YAML 字段。真实 Linux 重启和 supervisor 集成不在本机模拟测试覆盖范围内。

## 验证记录

- Bash 语法检查通过，公共 CLI 帮助入口通过。
- Python 安装器回归共 31 项：30 项通过，1 项跳过（本机 Windows 没有 Linux systemd-analyze）。覆盖原下载/校验/Docker、两种服务管理器生命周期、离线补注册、开关自启、归属拒绝、旧单元升级、启用/启动失败与原子替换失败清理。
- 测试在 Git Bash + Python 下执行，所有服务命令和注册目录均隔离模拟；NTFS 不校验 POSIX mode bits。Linux CI 有 systemd-analyze 时会执行真实单元语法验证，本机未做服务器重启/实际 supervisor 集成验收。
